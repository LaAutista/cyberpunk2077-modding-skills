# Retargeting workflow evals

The `native-normalization-domain` case applies the measured native leaf's input
range and MXCSR limits without treating a double equation as universal parity.
The `vehicle-direct-completion` case checks direct child contributions and the
parent's still-pending count during incremental submission, while preserving
the distinction between a vehicle owner and V's selected clock. Neither case
authorizes a game run; fresh independent evaluation is separate from root checks.

[Cases and trigger prompts](retargeting-cases.json) test agent decisions separately
from deterministic Python/native helper tests. [minimal.json](fixtures/minimal.json)
is synthetic two-bone data with intentionally synthetic identity hashes. It is not
a game skeleton or a certified source decode.
The [rig-mask fixture](fixtures/rig-mask.json) is a synthetic ten-bone hierarchy for
`masked-locomotion-carrier`; it establishes only the supplied composition example.

The `port-batch` fixtures are synthetic AnimData references and native-shaped JSON
for `accepted-release-batched-port`; their payload bytes are not animations.

The source-reference finger, double-mount and full-set/audio cases supply only
measurements or scenario facts. They test diagnosis, preservation and acceptance
decisions, not actual rendering or game behavior. No source assets are required;
claiming to have watched or installed a candidate from those facts is a failure.

The graph transition case supplies an explicit scalar offline formula and clock;
it tests a useful calculation plus the boundary at unknown interruption semantics.
It is not a native graph fixture or evidence of REDengine interpolation. Run the
graph-only trigger alongside the existing static-fitting negative trigger.

The pinned native cases instead identify a specific executable and its recovered
branches. They test use of documented implementation evidence: track presence,
priority/forced selection, transition versus capture curves, nonunit-scale
capture, Hermite value ordering and layout compatibility. They must yield the
supported derivations without promoting those derivations to game observations.
The clock/sync/shared-pose case also covers dilation branches, quintic decay,
database row precedence, target-event lookup, concrete receivers, tagged write
order and local aggregate publication. Run the unpinned synthetic interruption
case too: evidence for a named executable must not leak into an unspecified one.

The skinning/duration-setting case tests the concrete attachment-to-component
path, name/cache mapping, noncommuting matrix order, 48-byte output, bounds,
eye/auxiliary separation and the concrete signed missing-track address rule. It also distinguishes an
initialized setting default from an observed live value and reflected property
names from execution semantics. Synthetic derivations cannot clear a character's
runtime or visual acceptance.

The float-backend case separates explicit-address reads, secondary ordinal
lookup, current-buffer clearing and write-pointer rotation from renderer use.
The state/scratch case distinguishes fresh graph payload, authored history setup,
later no-write reuse, arena cursor release and candidate dispatch precedence.
The keyed-record/factor case checks matched coefficient remapping against
unmatched attenuation, input-order/duplicate behavior and untouched storage;
it also separates a clamped requested factor from curve-driven output and
inertia initialization from application at zero time/duration.
Use the current named build references; keep each arithmetic/model result
separate from native execution and actual selected game values.

The named-operator case distinguishes absent scalar handling, center-swapped
selection, radial remainder arithmetic, duplicate override descriptors, dynamic
mask admission, temporary auxiliary defaults and compiled output domains. The
motion-adjuster case separates the two auxiliary solvers, overshoot and lifecycle
rules, noncommuting correction order and one-turn extraction interpolation.
Their explicit synthetic inputs test application of the recovered contracts;
they do not establish native numerical parity or a selected gameplay path.

The rig-mask compiler case tests first-insertion/tree precedence, missing roots,
independent special membership and cursor admission, signed16 name encoding and
fresh versus repeated map construction. The property/producer case separates
value access from playback, source-handle identity and successful notifications,
finite bit-preserving scalar sorting from positional pose links, and provider
parent delegation from node-query construction. Execute the supplied bounded
examples; no native resource or game run is implied.

The collection-query case distinguishes separate contexts, branch priority,
signed time processing, one-cycle extraction, result write footprints, full-clip
record/event counts and cleanup ownership. The host-admission case tests ordered
gates and unsigned comparison after signed16 map loads, including a nonmonotone
map and storage reads before rejection. Both require executed finite checks and
keep queried outputs separate from accumulated auxiliary application. A passing
model does not establish native execution, caller reachability or live controls.
The full-clip producer case adds strict descriptor capacity, failure after partial
writes, logical invalidation, newest-record annotations and the unproved reset
boundary. It must use the typed producer rather than leave every optional query
constructor unresolved or relabel a cached descriptor as movement application.
Include empty-source event conversion with preexisting output: no entry reset
does not imply final count preservation, because validation still runs. Check
the resulting count/return and the outer producer's ignored return separately.

The timer/mesh-roundtrip/auxiliary case tests physical seconds, cap-before-scale
and owner clock replacement, then distinguishes flat orphan reconstruction from
the importer's local-transform helper and legacy preservation branch. Its typed
SkAnimAdjuster channel check must preserve the difference between production and
later entity application. Small arithmetic checks exercise the supplied inputs;
they do not execute the named native or WolvenKit implementations.

For each workflow case, start an independent evaluation with the current skill
and only that case's `prompt` plus relevant raw fixtures. Keep `must_observe` and
`must_not_observe` with the reviewer; do not feed the answer rubric to the evaluated
agent. Use a temporary workspace, synthetic files and read-only source assets.
Do not install a mod, start a game or contact anyone to evaluate the skill.

Review actual outputs and mutations against every criterion. Record skill/source
hash, case ID, model/harness, commands, artifacts, observed decisions, pass/fail
and limitations in a local report outside this distributable skill. A proposed
test is not an executed discriminator; a refusal alone does not satisfy a case
that calls for a concrete failure record or derivation. Retain failing transcripts
and change the skill only when a demonstrated decision warrants it.

For trigger cases, expose the three skill descriptions to a fresh evaluator with
the prompt and record selected skills. Do not expose `activate`. Positive prompts
should select this skill; pure static fitting, texture, audio or gameplay requests
should route elsewhere. A description review is not a live host auto-routing test.
Codex `skills/list` proves discovery/enabling only, not selection on real prompts.

From the repository root:

```sh
python3 -B -m unittest discover -s tests -p 'test_retarget_contract.py' -v
python3 -B skills/cyberpunk2077-animation-retargeting/scripts/retarget_contract.py validate-fixture skills/cyberpunk2077-animation-retargeting/evals/fixtures/minimal.json
python3 -B skills/cyberpunk2077-animation-retargeting/scripts/retarget_contract.py verify-mapping skills/cyberpunk2077-animation-retargeting/evals/fixtures/minimal.json
```

These deterministic checks exercise valid and corrupt contracts, hash preservation,
evidence categories, missing runtime/visual proof and the failed-attempt breaker.
They do not execute the behavioral prompts or prove game-level retarget quality.

The `animated-anchor-not-rotation-only` case uses the synthetic three-joint
[animated anchor fixture](fixtures/animated-anchor.json). Its255mm middle-key
translation returns to the original endpoint; it is a detector fixture, not an
RPG7 asset or recommended native joint edit. Run `inspect-source-motion` and
check the reported channel/time and OPEN disposition. The accompanying skin
acceptance case tests the validation escape and secondary-damage decision with
supplied measurements only; actual wire/opaque/playback review cannot be claimed.

The `finger-parent-transport` case exercises a noncoplanar parent/child rotation
where both final rays match but the world orientations differ. It tests the
declared twist contract and actual-skin evidence boundary, not surface fidelity.

The `preview-normal-boundary` case separates a missing authored-normal path from
real pose deformation using a fixed-pose arithmetic discriminator. The owning
RPG7 regression also compares actual evaluated Blender corners and unchanged
vertices; neither arithmetic nor shading success accepts the wrist/grip motion.

The `coupled-between-key-contact` case keeps the analytic grip rigid while sparse
local-channel interpolation shortens it. Run the endpoint and midpoint arithmetic
and distinguish approximation from serialization. The real RPG7 regression uses
its frozen approved curve and native readback; neither check is visual/game proof.

The `locomotion-caller-overwrite` case distinguishes helper-local repetition
arithmetic from the mode3 caller's retained duration, independent temporal/motion
scales, and zero-direction behavior. It also keeps fresh allocation separate from
reactivation and a per-graph auxiliary separate from final entity movement.

The `optional-query-buffer-history` case distinguishes the two query success
rules, caller-owned result history and array ordinals from provider IDs. It uses
explicit no-write-child premises; it cannot demonstrate native reachability,
an in-game stale-result defect or the graph-context/final-movement joins.

The `query-context-pointer-construction` case distinguishes the allocated context
from its provider header, captured pointer values from changes to their pointees,
and fresh null setup from hypothetical reuse. It also keeps the embedded-context
version read distinct from an AnimGraph property. Execute its bounded pointer
assertions; the constructor join does not clear later lifetime/runtime gaps.

The `query-context-revision-teardown` case checks conditional revision updates,
32-bit wrap, repeated calls without a new change, and pointer clearing before
release. Keep the primary D pointee distinct from graph G and embedded address
X. Execute the finite checks under the supplied no-alias-write premises;
callback purity, all mutation producers and runtime scheduling remain unproved.

The `query-context-batch-invalidation` case distinguishes idempotent key bits
from unconditional nonempty-batch invalidation, coalesced revision advancement,
empty input and what local host order alone proves about refresh. It also checks pending-flag
history independently of whether the current key operation changed a bit.

The `final-merge-clipping-audit` case checks cumulative accepted-clip preservation,
final-native audit identity/coverage and the limit of surface crossings for
embedded fingers. An old draft or a clean new clip cannot clear a stale final
bank. Run the owning project's actual merged-bank and surface checks; the case
itself supplies no game assets and cannot certify gameplay.

The `policy-cached-delta-and-stage-order` case follows the actual cached input,
including a disabled driver's store, and separates policy pre-update, update and
conditional query refresh. It distinguishes submission-only evidence from the
separately connected nested-job contract, and vehicle work from V evidence. Execute the finite
cases; no scheduler trace, native parity or character acceptance is supplied.

The `nested-stage-completion` case exercises parent/child pending counts, completion
before/during/after finalization and multiple parallel workers. Execute the finite
sequence and premature-completion counterexample. Use the ordinary-path premises;
the newer static dependency proof does not establish V's selected policy, a live
frame's ordering, native concurrency/parity or a fixed one-frame refresh delay.
